- **Secret preservation.** `persistImapSyncWatermark` spreads the current credentials, so `passwordEncrypted` stays encrypted and is never decrypted or re-encrypted on this path.
- **Minor race (non-blocking).** `persistImapSyncWatermark` (`imap-sync.ts` ~L321-354) reads the credentials, then writes the full JSON back through `updatePostApplicationIntegrationSyncState`. That update is matched on row id only, not on the credentials it read. Suppose a disconnect (credentials set to null) or a same-host/username reconnect with a new password lands between that read and the write. The sync would then write the old credentials, including `passwordEncrypted`, back onto the row. Before this change the sync never wrote `credentials`, so this is new. The window is two awaits on local SQLite and affects only the caller's own row, so I'm not blocking on it. A cheap hardening would be to do the read and write in one transaction, or to add a compare-and-set condition on `updatedAt` / the prior credentials.
